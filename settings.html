Dedicated Prompter
A separate LLM call reads the chat and writes the image prompt, so the roleplay model never has to emit [[IMG: ...]] markers.
In Dedicated mode [[IMG: ...]] markers are no longer a trigger — the prompter decides on its own, and you can delete the marker instruction from your Post-History Instructions. In Both mode markers win: the prompter stands down on any message that already got an image from one. Every bot message also gets a button for running the prompter by hand.
ComfyInject stores the profile id only — the model, endpoint and API key stay in SillyTavern. With no profile selected, the currently active main API is used instead.
Native falls back to prompt-engineered on its own if the backend refuses a schema.
The schema JSON is about 1,900 characters. On Auto it is left out of OUTPUT RULES while the backend enforces the schema itself, and the request is rebuilt with it if the backend refuses mid-flight. The prose rules and the worked example are always sent. Worth turning on for a small local prompter model, where those characters are noise competing with the instructions.
Always is an illustrated log: one image per character message, and the prompter's only job is deciding what to draw. Judge lets it skip a message it thinks shows nothing new. User messages never produce an image in either case. Switching this also switches which text Restore default writes into Prompter Instructions below; an unedited field is swapped over for you, an edited one is left alone.
Max tags truncates the prompter's tag list at a comma, enforced after the reply comes back rather than asked for in the prompt. 0 = off. It bounds only what the prompter writes — Prepend Prompt, the shot tag and Append Prompt are added afterwards and are not counted.
Comma-separated tags the prompter may not write, e.g. 2girls, multiple_girls, hug, hand_holding for a checkpoint that can only compose one figure. Stated in OUTPUT RULES and removed from the reply either way, before Max tags counts. Whole tags only — banning spine leaves spine_tattoo alone — and _ counts as a space, so banning either of hand_holding and hand holding catches both. Nothing here reaches the appearance registry either. This is not the Negative Prompt: that steers the image model, this stops the text model writing the tag at all.
With seeding off the registry still fills itself from generated images, and you can still seed it by hand from Appearance Registry below.
Present keeps the character card's own cast plus anyone named in the target message or the history window. It is for a long chat with many walk-on NPCs; the known cost is that someone referred to only as "the innkeeper" or by a pronoun is dropped, and their next image may contradict their last. It also moves the registry into the changing half of the request, so on a backend that caches prompt prefixes — a Claude profile, for one — All is usually cheaper as well as better.
How many messages before the target message the prompter sees. This is the largest changing part of every request, so it is the biggest lever on cost — a handful is usually enough for room continuity and pronouns. Anchor stride holds the window's start still for that many messages at a time instead of sliding it by one every turn, so the text is append-only between jumps; 0 slides.
Entries are read in dry-run mode, so the main chat's sticky, cooldown and recursion state is never touched.
Restore default
Rendered as the TASK section, first. Role and framing. There is one shipped default per Generate Policy; Restore default writes whichever matches the policy you are on.
Rendered as the CONSTRAINTS section, right after Prompter Instructions. Left out entirely when empty. This is the slot for standing facts about your checkpoint rather than your story — "renders one figure only", "the camera is never the user's eyes" — so you never have to rewrite the shipped instructions to state one. It sits in the unchanging half of the request, so a long block here is sent once and cached rather than re-sent every message; put short overrides that have to win in Final Instructions instead.
Restore default
The prompt inside the worked example in OUTPUT RULES. An example of a good reply outweighs instructions describing one — if your checkpoint only handles simple scenes, shorten this rather than asking for shorter prompts above.
Rendered as the last section of the request, after the target message. Left out entirely when empty. This is the recency-strong slot: a rule stated here is the last thing the model reads before the ask, so it beats a contradicting rule in Prompter Instructions. The seeding pass has its own — a standing framing usually belongs in both.
Restore default
The ask, appended at the end of the request's user message — after the target message and Final Instructions. Emptying it falls back to the shipped default.
Restore default
The appearance registry's seeding pass is a second, separate call with its own job, so it has its own instructions. Reached automatically once per chat, and on demand from Seed from card + lore in the registry editor.
Restore default
The example registry entry in the seeding pass's own OUTPUT RULES.
The seeding pass's own last section, left out entirely when empty. Separate from Final Instructions on purpose: generation policy means nothing to a pass that only extracts appearance tags. If you needed a standing framing up there you probably need one here too — the seeding call runs first, and a refusal leaves the registry empty, which degrades every image after it.
Restore default
The user message that asks the seeding pass for its reply. Emptying it falls back to the shipped default rather than to User Turn above, which asks for an image directive.
